# csirender

![Version](https://img.shields.io/badge/version-v0.2.0-blue)
![Go](https://img.shields.io/badge/Go-1.21+-00ADD8?logo=go)

`csirender` — это мощный, расширяемый движок декларативного 2D-рендеринга, написанный на Go. Он позволяет проектировать динамические дашборды и интерфейсы с помощью простых YAML или JSON конфигураций и рендерить их в стандартные изображения (PNG, BMP) или сырые данные, оптимизированные для EPD (e-ink) экранов.

![Пример рендера](examples/assets/images/example_render.png)
*(Изображение сгенерировано автоматически из файла [`examples/assets/example.yaml`](examples/assets/example.yaml))*

---

## 🚀 Возможности

- **Декларативная конфигурация**: Описывайте весь макет (текст, графики, карточки значений, линии, изображения, фигуры) прямо в YAML/JSON, не написав ни строчки кода для отрисовки.
- **Динамическая стилизация (Thresholds)**: Изменяйте цвета, фон, пути к картинкам и прозрачность на лету на основе телеметрии (например, сделайте фон красным, если `temperature > 30`).
- **Богатый набор элементов**:
  - **Текст**: Поддержка кастомных TrueType шрифтов, автоподгон размера (fit_text), шаблоны.
  - **Изображения**: Поддержка PNG/JPEG/GIF, режимы масштабирования (fit, stretch, center) и альфа-канал.
  - **Графики (Charts)**: Встроенные линейные графики с настраиваемыми осями и пороговыми линиями (threshold lines).
  - **Фигуры (Shapes)**: Прямоугольники, круги, эллипсы и многоугольники с динамическим вращением (идеально для стрелок компаса).
- **Расширяемая архитектура**: Реализуйте интерфейс `CustomRenderer` для создания специфичных для вашего домена компонентов с помощью системы плагинов.
- **Оптимизированное кеширование**: Встроенный обобщенный `Parser[T]` прозрачно загружает, кеширует и отслеживает изменения файлов конфигурации, гарантируя, что парсинг происходит только при необходимости.

## 🛠 Руководство по встраиванию

Библиотека `csirender` спроектирована для глубокого встраивания в ваши бизнес-приложения.

### 1. Определение конфигурации приложения
Вы можете расширить базовую структуру `LayoutConfig` собственными полями (например, настройками портов или БД):

```go
package main

import (
	"fmt"
	"github.com/ABespalov/csirender"
)

// AppConfig расширяет csirender.LayoutConfig вашей бизнес-логикой
type AppConfig struct {
	csirender.LayoutConfig `yaml:",inline" json:",inline"`
	ListenAddr             string `yaml:"listen_addr" json:"listen_addr"`
}

// Создаем кеширующий парсер для вашей структуры
var parser = csirender.NewParser[*AppConfig]()

func main() {
	// Parse загружает и кеширует конфигурацию
	cfg, err := parser.Parse("layout.yaml")
	if err != nil {
		panic(err)
	}
	fmt.Printf("Запуск сервера на %s с шириной экрана %d\n", cfg.ListenAddr, cfg.Screen.Width)
}
```

### 2. Подготовка телеметрии и рендеринг
Создайте движок (`Engine`), передайте ему живые данные через `RenderData` и получите готовое изображение.

```go
engine := csirender.New()

// Для обратной совместимости оборачиваем словари в MapDataProvider,
// или реализуем собственный DataProvider для "ленивых" вычислений!
data := &csirender.MapDataProvider{
	Data: csirender.RenderData{
		Values: map[string]interface{}{
			"temperature": 28.5,
			"weather_condition": "sun",
		},
		Charts: map[string][]float64{
			"temperature_history": {20, 22, 25, 27, 28.5},
		},
	},
}

// RenderWithProvider возвращает image.Image
img, err := engine.RenderWithProvider(&cfg.LayoutConfig, data)
if err != nil {
	panic(err)
}

// Теперь img можно закодировать в PNG/BMP и отправить клиенту или на дисплей
// Или использовать csirender.EncodePartialImage(oldImg, img, "epd_pr", ...) для частичного обновления E-Ink экранов!
```

*Полный рабочий пример клиент-серверной архитектуры находится в папках [`examples/server/`](examples/server/) и [`examples/client/`](examples/client/).*

## ⚙️ Справочник по конфигурации

Вся логика строится вокруг структуры `LayoutConfig`. Ниже представлен подробный разбор её ключей.

### Глобальные настройки

| Ключ | Описание |
|---|---|
| `screen.width` / `height` | Размеры холста в пикселях. |
| `screen.anti_aliasing` | Boolean. Включите для сглаживания или отключите для пиксель-арт рендера (полезно для e-ink). |
| `screen.palette` | Словарь для маппинга логических имен цветов на Hex-коды (например, `white: "#FFFFFF"`). |
| `output.format` | Формат вывода (`png`, `bmp`, `epd_raw`, `epd_pr`). |
| `output.background` | Базовый цвет фона холста. |
| `fonts.<name>` | Объявление шрифтов. Укажите `file` (путь к `.ttf`), `size` и режим `hinting` (`full`, `vertical`, `none`). |

### Элементы (Elements)

Все визуальные элементы имеют общие базовые свойства:
- `type`: Тип элемента (`text`, `value`, `chart`, `line`, `image`, `shape`).
- `position`: Координаты `x` и `y` от верхнего левого угла.
- `size`: Размеры `w` и `h` (ограничивающий прямоугольник).
- `source`: Ключ телеметрии, на который реагирует элемент (например, `temperature`).

#### 1. Текст (`type: text`)
Отображает статические или динамические строки.
- `template`: Строка шаблонизации.
- `font`: Ссылка на шрифт из глобального блока `fonts`. Определяет `face`, `fg` (цвет текста) и `bg`.
- `align`: `h` (`left`, `center`, `right`) и `v` (`top`, `center`, `bottom`).
- `fit_text`: Boolean. Автоматически уменьшает шрифт, чтобы текст поместился в заданный `size`.

#### 2. Карточка значения (`type: value`)
Сложный компонент, состоящий из `value` (значение), `label` (заголовок) и `unit` (размерность) внутри опциональной рамки (`border`).
- `format`: Форматирование в стиле `fmt.Sprintf` (например, `%.1f`).
- `value`, `label`, `unit`: Настраиваются отдельно (свой `font`, `align`, `template`).
- `border`: Настройки рамки (`t`, `color`) и заливки (`bg`).
- **Динамические пороги**:
  ```yaml
  thresholds:
    - condition: "val > 30.0"
      bg: red
      fg: white
  ```

#### 3. График (`type: chart`)
Отрисовка исторических данных (массивов).
- `points`: Количество точек на оси X.
- `axis`: Настройка осей `x` и `y` (видимость, подписи, шрифты).
- `threshold_lines`: Горизонтальные линии-маркеры на графике по заданному значению `value` с кастомным `color` и `style` (например, `dashed.4.4`).
- `thresholds`: Заливка областей графика в зависимости от значения.

#### 4. Изображение (`type: image`)
Отрисовка растровых картинок.
- `path`: Путь к файлу.
- `mode`: `fit` (сохранение пропорций), `stretch` (растяжение), `center` (оригинальный размер по центру).
- `opacity`: Непрозрачность от `0.0` до `1.0`.
- **Динамическая смена**:
  ```yaml
  thresholds:
      - condition: "val == 'rain'"
        path: "examples/assets/images/rain.png"
  ```

#### 5. Фигура (`type: shape`)
Геометрические примитивы.
- `kind`: `rect` (прямоугольник), `circle` (круг), `ellipse` (эллипс), `polygon` (многоугольник).
- `color`: Цвет заливки.
- `border`: Настройки контура.
- `sides`: Количество углов (для `polygon`).
- `rotation`: Статическое вращение в градусах.
- `rotation_expr`: Выражение для динамического вращения, привязанное к телеметрии (идеально для компаса или стрелочных приборов).

## 📜 История изменений (Changelog)

### v0.2.0
- Внедрена функция `EncodePartialImage` для поддержки инкрементального (частичного) обновления E-Ink экранов в формате `epd_pr`.
- Добавлен алгоритм поиска "грязных" зон по сетке 8x8 пикселей для вычисления минимальных ограничивающих прямоугольников (bounding boxes) между кадрами.
- Интерфейс `DataProvider` пришел на замену структуре `RenderData` для ленивых вычислений телеметрии.
- Добавлен метод `RenderWithProvider` для нового API.
- Сохранена обратная совместимость со старым API `Render` через обертку `MapDataProvider`.

### v0.1.0 (Первый релиз)
- Ядро декларативного 2D-рендеринга.
- Поддержка элементов `text`, `value`, `chart`, `line`, `image` и `shape`.
- Кеширующий парсер `Parser[T]` для эффективной перезагрузки конфигов.
- Поддержка динамической стилизации (Thresholds).
- Расширяемый интерфейс `CustomRenderer`.
